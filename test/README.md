# Test environment

Local dev cluster per Elastic's [local-development quickstart](https://www.elastic.co/docs/deploy-manage/deploy/self-managed/local-development-installation-quickstart), plus fixtures for running the `dist/audit` smoke tests against it.

## What's here

- `start-local.sh` — Elastic's `elastic.co/start-local` bootstrap, **locally patched**: the `docker-default` AppArmor profile on recent Docker/Ubuntu blocks the JVM self-attach ES 9.x uses for its entitlement agent (`Unable to attach entitlement agent … Permission denied` while "Bootstrapping Entitlements"). The patch adds `security_opt: [apparmor=unconfined]` to the elasticsearch service. The same wall will be hit on any Ubuntu 26.04+ docker host, including offline ones.
- `elastic-start-local/` — generated by the script: `docker-compose.yml`, `.env` (random `elastic` password + API key), `start/stop/uninstall.sh`. **Gitignored — contains credentials.**
- `stub.py` — dev stub serving `dist/ear` as the EAR plus canned EPR `/health`+`/search`+zip endpoints on `127.0.0.1:9911`.
- `inputs.local.yml` — auditor inputs for this testbed (**gitignored — holds the dev-cluster password**).

## Use

```bash
sh start-local.sh -v 9.5.7            # bring the cluster up (idempotent-ish; creates elastic-start-local/)
EAR_DIR=dist/ear python3 test/stub.py &   # EAR/EPR stub on :9911
dist/audit/run.sh test/inputs.local.yml   # 13 controls: stub EAR/EPR + real ES/Kibana
elastic-start-local/stop.sh           # stop
elastic-start-local/uninstall.sh      # remove containers + volumes
```

## Verified

`23 assertions / 0 failures` against the real 9.5.7 containers — ES `/` tagline + `/_cluster/health` green + unauth 401, Kibana `/api/status` + `/login` (302 when authenticated). To test a real deployed EAR/EPR instead of the stub, point `ear_url`/`epr_url` at them.
